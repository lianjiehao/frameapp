# 架构说明

[English](architecture.md) | [简体中文](architecture.zh-CN.md)

## 建议阅读顺序

1. [main.dart](../lib/main.dart)：应用启动、同意流程接入和相机页面。
2. [CameraCoach](../lib/services/coach.dart)：通过 `ChangeNotifier` 统筹阶段、相机生命周期、分析与拍照，页面监听状态。
3. [core](../lib/core/)：像素归一化、选中主体跟踪、画面证据、构图排序与稳定判断。
4. [平台服务](../lib/services/)：通过条件导入区分原生／Web 的拍照、保存和本地政策渲染。

~~~text
图像输入
  → pixel_buffer：方向、镜像、3:4 居中裁剪
  → GrayFrame：192×256 跟踪；96×128 画面分析
  → subject_tracking + vision + scene_evidence
  → composition：候选排序、目标选择、稳定判断
  → CameraCoach → main.dart + ui/guides.dart
  → camera_photo → gallery（原生相册／Web 下载）
~~~

`coach.dart` 中的 `CapturePhase` 为 `framing → analyzing → recommending → guiding → ready → capturing → captured`。直接拍照、重置、重试、挂起及跟丢会分叉；调整阶段前先读控制器。原生相机采样与分析在同一个 `compute` 任务中完成，约每 120 ms 请求一次，忙碌时只保留最新待处理帧及其原始采样时间。相机裁剪区域先做面积加权平均，再缩小到 192×256，避免细枝、草叶在轻微移动时产生混叠噪点。控制器同时更新采样画面和分析结果；已经过期的结果不能恢复实时锁定或拍照就绪。

普通原生构建从拍照指南或相机错误页进入练习模式后，顶部提供「退出练习」。退出会停止练习采样、清空主体选择与构图引导，再经过现有的隐私同意和相机权限检查恢复取景；此前拒绝过权限时，仍须主动点击重新开启相机。Web 和 `DEMO_MODE=true` 构建保持仅练习模式。`practice_mode_test.dart` 覆盖从指南进入、引导中退出、状态清理、权限拒绝和窄屏顶部布局；真实相机恢复仍须真机验证。

`ui/camera_help.dart` 将拍照指南排为三个编号步骤，拍摄提示使用较弱的视觉强调。练习入口为底部独立区域的整行按钮，与可滚动正文分开，短屏和大字号下仍可直接操作；隐私入口保留在标题右侧，练习模式下隐藏练习入口。

## 选中主体跟踪

先在上次确认的特征点位置附近做短距离光流跟踪；只有局部一致性不足时，才使用全画面位移预测来处理较大平移，避免重复按键或文字行把框拉到远处相似图案。局部角点共识预测移动后，再用点击位置周围较大的图像块做双向光流与外观校验，修正透视、自动对焦模糊或曝光变化引起的中心漂移。补充角点限定在当前主体中心周围的固定屏幕范围内，避免放大后扩大到远处背景。最初的选择模板保持不变；遮挡、主体出画仍会撤销可见锁定框。

每个分析帧和跟踪快照记录对应的相机倍率。倍率变化后，后台任务先按居中裁剪关系映射此前已验证的像素、中心和角点，再与新画面匹配。缩小时新露出的未知边缘不参与全画面位移预测；原模板在新尺度上仍高度匹配时，用它校正反复缩放的重采样偏移。仅有预测位置不能恢复跟踪。变焦请求开始时立即撤下旧框和拍照就绪状态。回归测试覆盖已知透视变换、重复键盘纹理、真实像素双向缩放、非默认倍率下选中主体、遮挡，以及目标靠近框边缘时正常完成并保持拍照就绪。

画面分析过期时，预览区点选会排入重新选择请求，不再直接忽略。原有的最新帧队列优先采样新画面，不再先尝试跟踪旧主体；只保留最后一次点击和最新待处理帧。过期像素不能建立锁定，失效任务的结果或错误不能覆盖新选择。重新取景、调焦、拍照和挂起会取消待处理点击；重新锁定后重新开始稳定计时。

## 相机倍率

每次初始化后置相机时读取设备实际支持的最小、最大倍率，按对数范围规划三个不重复的档位，并向下取常用数值；窄范围退回最小值、中点、最大值。例如 1–10× 生成 1 / 2 / 4，1–20× 生成 1 / 2 / 6，不支持的档位不显示。实时倍率低于第二档时显示在左侧，低于第三档时显示在中间，达到第三档后显示在右侧；1 / 2 / 4 对应 [1, 2)、[2, 4)、[4, 最大倍率]。轮盘标注包含三个档位、真实范围端点及范围内间隔适当的常用数值。这些是变焦快捷档位，不代表光学镜头倍率。从倍率条开始左右滑动会展开半透明圆弧轮盘，并定位到当前倍率。向左滑动放大，细密的对数刻度跟随手指位移，在固定的黄色指示线和实时倍率下方转动。手势采用增量输入，到达上下限后反向滑动立即响应。重新按住轮盘时从当前倍率继续调节，不跳变。轮盘不设展开或收起按钮。手指按住时保持显示，最后一根手指松开或触摸取消后，等待 1 秒再淡出。等待期间点击屏幕立即收起；预览内用于收起的点击不会同时选中主体。触摸预览外的区域也会收起轮盘。控件移除时取消计时器。

双指缩放预览区会调节相机倍率，倍率条通过动画收拢为一个居中的实时数值，不展开轮盘；最后一根手指松开或触摸取消后，三个档位通过动画恢复原位。拖动轮盘时加入第二根手指会切换到双指缩放，松开其中一根手指不会重新展开轮盘。点击常用倍率直接切换到目标数值，不播放数字增减动画，也不展开轮盘。选中背景与倍率条保持相同高度和圆角，在左右端档位与外侧边缘贴合。两种调节方式均遵循设备支持范围。控件覆盖在 3:4 预览之上，不改变预览大小；实时预览、分析帧和最终照片使用同一相机倍率。手势期间控件直接跟随本地触摸更新，不等待相机回执；倍率通知只重建缩放控件。界面接受的每个倍率变化都会传给相机，包括跨过显示舍入或档位边界的亚像素变化，避免松手时恢复旧值；旧请求的延迟回执不会覆盖最新待处理倍率。整个调节手势期间跳过新到的预览采样，只保留最新倍率请求；倍率成功应用后，丢弃旧画面、构图建议和稳定计时，并保留已选主体以便新画面重新跟踪。预览状态提示统一显示在右上角。前置相机不查询变焦范围，不显示倍率条或轮盘，也不接受双指缩放或变焦请求；切回后置时重新读取范围并规划档位。后置相机不支持变焦或范围只有单一数值时隐藏控件。练习照片和 Web 模式不提供相机倍率。

`camera_zoom_test.dart` 覆盖动态档位和范围端点、前后置切换及前置变焦禁用、设备倍率范围映射、连续请求串行化与合并、设备失败和重置、手势范围、延迟收起和取消、双指与拖动切换、常用倍率点击，以及倍率变化后的主体恢复。

## 改动定位

预览右下角的角度使用低亮度灰白色小字与轻微阴影，不设背景块，保留原有仰拍、俯拍、水平、左倾、右倾文案及对应度数，始终单行显示；传感器准备中、晃动及不可用提示仍优先显示。轮盘展开时随动画淡出，避免与边缘刻度重叠，也不拦截点选。预览下方的引导标题使用简短单行文案，超出时省略；右上角保留完整说明，提示变长不会再占用更多预览高度。

选中主体后的“一秒保持”指目标中心持续位于可见跟踪框内（取景宽度的 14% × 高度的 13%）。绘制和就绪判定共用这一尺寸。框内轻微移动继续计时并保留就绪状态。目标出框、主体跟丢、画面过期或传感器检测到剧烈晃动时重置计时。横向分界引导按线条容差判断；倾斜和构图质量仍属于建议。

## 照片滤镜

取景和调整构图阶段可在取景框下方打开滤镜。推荐结果页不显示快捷操作行，让预览区使用腾出的高度；进入前后仍可调整滤镜。切换镜头和闪光灯位于页面右上方、帮助按钮旁，顶部不设照片入口。滤镜提供原图、暖光、清透、胶片和黑白，支持调整强度。`PhotoFilter` 根据饱和度、对比度和通道平衡定义本地色彩矩阵。胶片额外绘制确定性的程序颗粒和暗角，黑白带轻微暗角；手动调节均为中性值时，样式强度归零会恢复原始像素。预设不需要下载资源或新增权限。

只有照片层经过 `FilteredPhoto`，引导线和文字保留各自颜色；跟踪与构图仍使用未调色的相机采样。预览和 PNG 导出共用同一配方及归一化纹理坐标。快门按下时固定配方，下一张照片前禁用滤镜修改；保存重试直接复用已拍摄的 PNG，不再次叠加滤镜。挂起时失效的进行中拍摄不能再发布或保存结果。

同一面板还提供亮度、对比度、饱和度和冷暖调节，中性值为零，界面显示范围为 −100 至 +100。本地调节合成在样式色彩矩阵之后、纹理之前；全部归零时保留样式输出。选择原图或将样式强度归零后仍可调节；重置只清除四项调节，保留样式及其强度。控件全部放在弹出面板内，不增加取景框下方的行数。拍照时固定的配方包含这些调节，保存重试仍使用同一成片。

`photo_filter_test.dart` 对比预览与导出像素，覆盖零强度、黑白输出、裁剪／镜像和保存重试。组件截图使用已有许可的示例照片。原生相机纹理、前后镜头方向、相册成片、权限中断及拍摄中切到后台仍须在 Android 和 iOS 真机验证；组件渲染不能证明设备上的色彩或性能一致性。

## 生成内容与素材

| 产物 | 来源与生成方式 |
| --- | --- |
| `assets/legal/`、`lib/services/policy_pages.g.dart` | `python3 tools/build_policy_pages.py`；正文在脚本中，配置在 `policies/config.json` |
| `assets/fonts/FrameSans-Regular.ttf` | `tools/update_ui_font.py` 根据 Dart／政策文本，从有许可的完整 Noto Sans SC 字体生成子集 |
| 构建目录、插件注册和本机 SDK 路径 | Flutter／平台工具生成，本机构建产物不提交 Git |

运营者、联系方式与同意版本由 `policies/config.json` 生成。`policy_pages.g.dart` 提供原生与 Web 共用的 HTML。应用通过 `frame-policy` URI 处理页面间跳转；点击 GitHub／邮件链接时才打开外部程序。

不要直接修改生成的政策副本。修改源文件后重新生成，一起审阅和提交副本，见 [本地政策页面](../policies/README.md)。

新增中文界面字符后检查实际显示。需要补字时，在虚拟环境安装 `fonttools`，执行 `python tools/update_ui_font.py /path/to/NotoSansSC.ttf`，保留字体许可并核对差异。只改 Markdown 文档无需重建界面字体。

内置照片和文档截图的许可见 [第三方与素材说明](../THIRD_PARTY_NOTICES.md)。展示截图不能代替真机验证记录。
